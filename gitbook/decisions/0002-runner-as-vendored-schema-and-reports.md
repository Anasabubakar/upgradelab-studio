# ADR 0002: Consume the runner as a vendored schema plus recorded reports

Status: accepted, 2026-10-07.

The studio must build from a clean independent clone, so it cannot import the runner by sibling path, and the runner is a Rust binary, not an npm package. What the studio needs from it is data: the report JSON Schema and real reports. We commit both under `vendor/upgradelab-runner/` with a `VERSION.json` stamp (runner version, git commit, schema sha256, per-report sha256), generated by `scripts/vendor-runner.mjs`. The schema is compiled to a standalone validator at build time (`scripts/gen-validator.mjs`, ajv) and the generated file is committed, so the page needs no runtime code generation and keeps a CSP without `unsafe-eval`. Tests fail if the stamp, the files, `compat.json`, `package.json` or the generated validator disagree.

Consequence: every report shown is real runner output; updating means re-running the runner's `scripts/record-evidence.sh`, then `pnpm vendor`, `pnpm gen`, `pnpm test`.
